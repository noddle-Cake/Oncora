## Stereochemistry: compoundinfo SMILES and InChIKeys disagree

The InChIKey recomputed by RDKit from `canonical_smiles` differs from the provided one for 93 DSS3 compounds, and for 1,137 / 28,618 (4.0%) parseable compounds across all of compoundinfo. In every DSS3 case (93 / 93) only the second (stereo) block differs: the provided InChIKey encodes stereochemistry that the provided SMILES has lost, or encodes differently.

Consequences:

1. **Splits must group by the connectivity block** (the first 14 InChIKey characters), not the full key. ECFP fingerprints are achiral by default, so stereoisomers have identical feature vectors. Splitting them across train and test would leak. The stereoisomer groups in DSS3 are listed below. Spec 04 has been updated to match.
2. **Cross-source matching** (compoundinfo ↔ ChEMBL ↔ user input) should use one InChIKey convention, computed by RDKit after the spec 03 standardization, and fall back to the connectivity block where stereo is missing on one side.
